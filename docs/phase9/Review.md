## Review requirements

- Authenticate each Parent and bind all reads/mutations to active, permanent same-family membership. Keep API execution allowlists explicit; client tables remain read-only under RLS. Pin security-definer search paths and keep the private schema outside exposed API schemas.
- Preserve first committed decisions. Compare expected versions atomically after acquiring the relevant lock. Refresh stale screens before another decision; a batch must report each item's actual outcome and cannot claim whole-batch success after partial failure.
- Enforce payload-bound request identity and independent economic source uniqueness. Different request IDs, timeout retries and simultaneous parents must not repeat approval, earnings, reward debit/refund or extra-outcome grants.
- Preserve rule and occurrence snapshots, effective dates, original task-day attribution and immutable first publication. A rule edit cannot relabel or recalculate submitted, published or sealed history.
- Keep duty contribution facts separate from finalized earned XP and spendable Coins. Revisions use full-state `F(new)-F(old)`, including the actual85 gate and ordinary100→200 bonus. Ordinary100→95 is -105;85→80 is -85. Each finalized XP effect has one linked Coin effect.
- Any accepted positive virtual conversion preserves day provenance: actual100 then earns100 even when virtualRemaining is0. Virtual protection earns nothing itself and cannot unlock actual earnings below85. Unsupported allocation/conversion/reversal workflows need explicit policy gates.
- Enforce effective seal at transaction completion. No client clock, queue timestamp, expiry-job lag, review delay, appeal or new request identity reopens a sealed result. Immutable late first publication alone creates the approved extension.
- Preserve saved reward prices, actual debit/refund linkage and earned-XP history. Pending cancellation creates no refund; approved unfulfilled cancellation refunds once. Extra outcomes require Parent confirmation; repeated confirmation cannot repeat an award.
- Shared history shows actors, reasons, versions and revisions with explicit pending/finalized/sealed status. Missing results are not confirmed bad days. Private health content must never enter family audit or scoring.
