# Private cycle vault

Use one `CycleVault` instance for the app. Call `prepareKey()` before the operating system authentication prompt, then `unlockAfterAuthentication()` only on success. The system device credential or strong biometric authorizes a 30 second Android Keystore window. There is no separate health PIN. Lock on background and screen-off; a generation token invalidates pending UI edits. All operations serialize with lock and commit; memory changes follow successful AtomicFile completion. Snapshots contain immutable objects/lists and must not be retained after lock.

No health values belong in SQL, preferences, logs, analytics, saved instance state or caches. Both encrypted files reside in `noBackupFilesDir/private_cycle`. Vault ciphertext uses AES-256-GCM, a random data key and fresh platform-generated IV per encryption; Android Keystore wraps the data key under authentication. Versioned binary header `50 51 43 56 01` is GCM AAD, followed by one IV-length byte (12), IV and ciphertext with 128 bit tag. AtomicFile reads recover its `.bak` file. Missing key, incomplete file pair, invalidated credential key or corruption fails closed. Explicit confirmed reset deletes only this journal and its Keystore alias. A lost device key cannot be recovered without a separately created encrypted export; reset never recovers old entries.

`exportEncrypted(token, password)` creates no plaintext file. Its JSON has three string fields: `metadata` (exact UTF-8 JSON text used as GCM AAD), `iv` and `ciphertext` (standard base64 without wrapping). Metadata contains `format: petalquest-cycle-backup`, `version: 1`, `kdf`, `iterations` and base64 `salt`. AES-256-GCM uses a 12 byte random IV and 128 bit tag appended to ciphertext. A random 16 byte salt derives a 256 bit key with PBEKeySpec password characters and PBKDF2WithHmacSHA256 / 600000 iterations on API26+, or PBKDF2WithHmacSHA1 / 1000000 on API24-25. Never normalize or trim a password. Future restore must accept only these bounded version/KDF/iteration combinations, validate dimensions and authenticate the exact metadata string before using decrypted data. Decrypted content is UTF-8 JSON with version 1, periods and observations matching the model fields. Password arrays, derived key bytes and plaintext byte buffers are cleared after export; Java Strings and provider internals cannot be reliably erased. The caller must discard UI text and snapshots on lock.

Backup requires explicit destination selection and fresh OS authentication. A password of at least 12 characters is required. Lost backup passwords are unrecoverable. Restore/import is deferred to Phase 11. Never save the password or journal through the destination picker lifecycle.

Period lengths are inclusive calendar days. Intervals between successive starts are a distinct statistic; no prediction is implemented. Dates are strict local ISO calendar dates; future dates, overlapping or duplicate periods and invalid pain scores are rejected. An ongoing period overlaps through today. Empty optional observations remain valid.

References: [Android Keystore](https://developer.android.com/privacy-and-security/keystore), [KeyGenParameterSpec](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec.Builder), [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile).
